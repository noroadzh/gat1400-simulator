## ADDED Requirements

### Requirement: Client MUST transparently handle Digest 401 challenge

When `Client.PostJSON` sends a request and receives `401 Unauthorized` with `WWW-Authenticate: Digest ...`, the client MUST automatically retry the request with a valid `Authorization: Digest ...` header computed from the challenge.

#### Scenario: Server returns 401 on first Register request
WHEN a Client.PostJSON to `/VIID/System/Register` receives a `401` with a valid Digest challenge
THEN the client MUST retry exactly once with the computed Authorization header
AND the final response MUST be returned to the caller.

### Requirement: Client MUST use crypto/rand for nonce generation

The `cnonce` value sent in the Authorization header MUST be generated using `crypto/rand`. Using `time.Now()` or other predictable sources is PROHIBITED.

#### Scenario: Predictable cnonce
WHEN `buildAuthorization` is called with a `cnonce` generated by `time.Now()`
THEN this MUST be flagged in code review as a violation of this requirement.

### Requirement: NonceStore MUST persist across restarts

Nonce values MUST be stored in a SQLite file. A client process restart MUST NOT invalidate nonces that are still within the server's validity window.

### Requirement: Duplicate nonce+nc MUST be rejected by server

The client MUST increment `nc` for each unique request using the same nonce. Sending the same `nc` value twice for the same nonce MUST result in server rejecting the second request with `401`.

#### Scenario: nc counter collision
WHEN two Register calls use the same nonce with `nc=00000001`
THEN the second request MUST fail at the server (401) because replay was detected.

### Requirement: User-Identify header MUST be sent on every request

Every HTTP request made by the Client MUST include `User-Identify: <node-id>` header.

### Requirement: Content-Type MUST be application/VIID+JSON

Every POST/PUT request body MUST be sent with `Content-Type: application/VIID+JSON`.

### Requirement: Digest response MUST use constant-time comparison

The server-side digest comparison MUST use `crypto/subtle.ConstantTimeCompare` to prevent timing attacks.

## ADDED Architecture Decisions

### Decision: NonceStore is a wrapper over storage.NonceStore

This avoids duplicating SQLite logic. The `NonceStore` in `adapter/wire` calls `storage.NewNonceStore` internally.

### Decision: Client retries only once

The client does not implement retry loops. If the second attempt also fails, the error is returned directly. This prevents infinite loops on misconfigured servers.
